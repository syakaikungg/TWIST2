# arm_ik: G1 の腕テレオペ（PICO → IK → rt/arm_sdk）

NexTech Week 2026 秋の展示用。G1 の内蔵PC（`~/nextech/arm_ik/`）で動かす。脚は純正の制御のまま、両腕と腰を `rt/arm_sdk` で上書きする。

| ファイル | 役割 |

| `arm_sdk_bridge.py` | Redis `arm_ik_q` → `rt/arm_sdk` の LowCmd。既定はログのみで、`--send` のときだけ送信する。`--sim` は `arm_sim.py` と Redis でつなぐ |

| `sim_drill.py` | シミュレーターのドリルの形と回し方（ビューアーからも使う） |
| `sim_viewer.py` | ノートPC（WSL）のビューアー。G1の `stream_sim.py` を SSH で動かして関節角を受け取り、MuJoCo の窓に描く。`sim_drill.py` と同じフォルダ（`~/nextech_viewer/`）に置く |

## 操作用のPC

テレオペはすべて G1 の内蔵PCで動く。操作用のPCは、LAN ケーブルで G1 につなぎ、SSH で起動と停止を頼むだけ。展示会では自宅の Ubuntu PC を使う（11/4 本人）。今のノートPC（Windows）は WSL の Ubuntu から同じことをしている。

新しいPCの準備（1回だけ）
1. 有線 LAN の IP を固定にする：G1 と LAN ケーブルでつなぎ、設定 → ネットワーク → 有線 → IPv4 を「手動」、アドレス `192.168.123.223`、ネットマスク `255.255.255.0`、ゲートウェイは空。`.164` は G1 の内蔵PC、`.1` は TP-Link ルーター、`.76` は PICO、`.222` はノートPC。設定する前に、G1 につないだ別のPCから `ping -c 2 192.168.123.223` が返らない（空いている）ことを確かめる。設定したら `ping 192.168.123.164` が返れば OK
2. SSH の鍵：`ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_g1`。公開鍵を G1 に登録する：`ssh-copy-id -i ~/.ssh/id_ed25519_g1.pub unitree@192.168.123.164`（G1 のパスワードを1回聞かれる）。G1 につなげないときは、公開鍵（`~/.ssh/id_ed25519_g1.pub`、人に見せてよい方）を送れば、つながっている別のPCから G1 の `~/.ssh/authorized_keys` に足せる。秘密鍵（`.pub` の付かない方）は送らない
3. このスクリプト：`git clone -b claude/project-thread-fv7uja https://github.com/syakaikungg/TWIST2.git`（公開リポジトリなのでログイン不要）。`bash TWIST2/deploy_real/arm_ik/g1.sh status` で G1 の様子が出れば準備完了

いつもの流れ
- 1回だけ：`bash g1.sh autostart`（G1 の sudo のパスワードを1回）。これで、次からの `g1.sh up` はパスワードを聞かない（Claude が SSH で実行できる）
- G1 の電源を入れたら：`bash g1.sh up` → PICO の XRobot → PC Service と Remote Vision → ZEDMINI → Listen → 有線なら `192.168.123.164`、Wi-Fi なら G1 の Wi-Fi のアドレス（`g1.sh up` の最後に出る）→ Confirm。`g1.sh autostart` の前は、`g1.sh up` が sudo のパスワードを1回聞く（端末からだけ）
- 腕を動かす：`bash g1.sh send 0.5 300`（ロボットに送る。止めるのは PICO の左 X、または別の端末で `bash g1.sh stop`）
- 送らずに試す：`bash g1.sh dry`

## 入力の記録と再生

IK は、PICO からの入力（頭と両手の位置と向き、ボタン、グリップ、トリガー、データの時刻）を、CSV の隣の `*_input.jsonl` に毎回書く（約20 kB/秒、`--no-record-input` で止める）。`--replay その.jsonl` で、同じ入力をそのときの時刻どおりに IK に流せる（PICO と Redis は使わない、ロボットには何も送らない）。設定を変えて2回流し、`compare_replay.py A.csv B.csv` で手の位置の差を見る。例：今の設定と、11/4 までの計算（`--heading per_arm --neck-back 0 --neck-down 0`）。同じ設定で流すと、元の自己テストと差は0.0 cm だった。11/4 までの記録は `csv_to_input.py` でおおよその入力に直せる（前の向きの比べ方には使えるが、首の位置の推定は頭の傾きが無いので比べられない）。

## 操作（PICO）

- 右A：開始／一時停止。開始すると準備（重みを3秒で上げる）が始まる。準備が終わってからグリップを握ると、手についてくる
- 右グリップ／左グリップ：握っている間だけ、その側の腕が追従する（デッドマン）。両方握れば両腕。離した腕はその場で止まる
- 手の位置は、毎フレームのヘッドセットから推定した自分の肩からの位置を0.68倍して、ロボットの肩から伸ばす（最初のコントローラーからの差分ではない）。肩は首の位置（ヘッドセットの9cm後ろ、11cm下、ヘッドセットの向きに合わせて回す）から推定するので、下や横を向いても手の目標は動かない（シミュレーターで見回したときの手の動き 5.4→1.0 cm）
- 「前」の向き：両手を離した状態から握った瞬間の顔の向きを、両腕の前にする（`--heading shared`、11/5〜）。片手を握っている間にもう片方を握っても、同じ前を使う。体の向きを変えたら、両手を一度離して、正面を向いて握り直す。握っている間に見回しても前は変わらない（11/4 までは腕ごとに握った瞬間の向きで、実機では左右が39°ずれていたことがある。`--heading per_arm` で戻せる）
- 右トリガー：ドリル ON（追従中だけ）
- 右スティックの押し込み：最初の姿勢に戻って一時停止（`--return-button`。B は Remote Vision の片目/両目の切り替えなので、何もしない）
- 左X/Y：非常停止（PC から起動し直すまで止まったまま）。重みは3秒で0になり、腕と腰は純正の制御に戻る（1秒だった11/4の実機では、腕が最大1.5 rad/s で戻った。シミュレーターでは3秒で1.8→0.6 rad/s）
- リモコンの L2+B は全身のダンピング（脱力）。腕だけの停止ではないので、吊っているときの最後の手段

## 自動で止まる条件

- 追従中（グリップを握っている）に PICO のデータが途切れたら、`--follow-stale`（0.5秒、11/10〜）までは腕をその場で止めて待つ（映像に「通信待ち」）。データが戻れば、握ったままの腕はそのまま追従を続ける（前の向きは途切れる前のまま。途切れている間に顔を横に向けても変わらない）。0.5秒を超えたら非常停止。途切れは「0.3秒新しいデータが来ない」から数える。11/10 の会場の Wi-Fi で0.30〜0.32秒の途切れが1回ずつ出たので、0.3秒ですぐ止めるのをやめた（`--follow-stale 0.3` で前と同じ）。途切れている間は左X/Yも届かない
- 追従していないとき（グリップを離している）の途切れは、`--stale-hold`（2秒）までは腕をその場で保って待つだけ。データが戻れば自動で元に戻る。2秒を超えたら非常停止
- ブリッジ側：IK の指令が0.3秒途切れた、指令と実測のずれが0.3 rad を0.5秒、腕か腰のモーターが `--max-temp`（`run_live.sh` では70℃、ブリッジ単体の既定は60℃）超、rt/lowstate が0.2秒途切れた、`stop.sh`
- 温度：ブリッジが指令しているモーターのいちばん高い温度を `teleop_state/bridge` の `temp`・`temp_joint` で報告し、上限の5℃手前（`run_live.sh` では65℃）から映像に「腰 62℃ 腕を下ろして休ませて」と出る。上限の根拠は Unitree の仕様ではなく、安全側に決めた値（Unitree の公開資料に上限は見つかっていない。11/4 純正の制御のままの左足首は62℃でも止まらなかった）。11/4 の5分の送るテストで右肩 pitch と腰 roll がちょうど60℃に届いたので、本人と相談して65℃にした。11/10、工具を右手首に付けて吊ったロック立ちで送ると、右肩 pitch が腕を支えるだけで8〜10 Nm を出し続け、57℃から約30秒の追従で65℃を超えて止まったので、本人の依頼で70℃にした。脚のモーター（0〜11、純正の制御）のいちばん高い温度も `leg_temp`・`leg_joint` で報告し、`--leg-temp-warn`（70℃）以上で映像に「脚 右足首 75℃ 休ませて」と出る（表示だけで止めない。11/4 右足首のモーター11が77℃まで上がった）。`--temp-pause 58` を付けると、その温度で最初の姿勢に戻って一時停止し、`--temp-resume`（55℃）以下になるまで A を受け付けない（既定はオフ、11/4 本人の選択で表示だけ）

## 表示用の状態（Redis `teleop_display`）

IK が毎ループ（50 Hz）書く JSON。PICO の映像に重ねる表示に使う。`t` が0.5秒より古ければ、IK が止まっている。

```json
{"t": 1762176000.0, "level": "ready", "ja": "握れば動きます", "en": "READY - hold grip",
 "ik": "ENABLED", "bridge": "TRACK", "weight": 1.0, "reason": "", "drill": 0}
```

`level` の値は次のとおり。

| level | 意味 | ja の例 |
|---|---|---|
| `stop` | 非常停止（IK か、ブリッジの見張り） | 非常停止（PCから再起動が必要）、非常停止（ブリッジ・PCから再起動が必要） |
| `warn` | PICO のデータ待ち、またはブリッジが応答していない | 通信待ち（データが戻れば再開） |
| `wait` | 準備中、または最初の姿勢に戻っている途中 | 準備中 あと2.1秒（そのあと握れば動く） |
| `idle` | 一時停止中 | 一時停止中（右Aで開始） |
| `ready` | 握れば動く | 握れば動きます |
| `ok` | 追従中 | 追従中 |

ドリルが ON のときは、文の後ろに「／ ドリルON」が付く。

## 腰

arm_sdk を有効にすると、腰（12〜14）もこちらの担当になる（公式の arm7 の例と同じ組み合わせ）。既定は TWIST2 の腰ゲイン（kp 150 / kd 4）と、roll・pitch の積分補正（`--waist-correct`）。シミュレーターでの腰の傾きは、最大0.03〜0.04 rad。ただし `run_live.sh`（`g1.sh dry/send`）では、11/10 から積分補正を切っている（`WAIST_CORRECT=roll,pitch` で前と同じ）。11/10 に工具を右手首に付けて立たせたまま送ったとき、腰がほとんど動かないのに補正だけが上限の0.15 rad まで増え、腰 pitch の力が4→24 Nm、温度が25秒で54→66℃に上がって止まったため。展示では、吊って脚を脱力させ、上半身だけを動かす（11/10 本人決定）

純正の立ち姿勢は腰 pitch が約 +0.11 rad（6°前傾）で、11/4 の実機ではそれをそのまま保っていた。腰の負荷は純正のときの約3 Nm に対して、追従中は平均8〜10 Nm、両腕を前に出すと最大18.7 Nm で、腰 roll のモーターが61℃になった。`--waist-level roll,pitch`（既定）で、右Aを押した直後（重みを上げる準備の間）から、腰の roll と pitch を0.03 rad/s でゆっくり0（まっすぐ）にする（0.11 rad なら約4秒）。IK のモデルも腰0を前提にしている。シミュレーター（sim_suite）では、腰 pitch のトルクの RMS が8.7→7.2 Nm、roll が2.2→0.5 Nm。`--waist-level ""` で前の動き（始めたときの角度を保つ）。ブリッジの CSV には骨盤の IMU（`imu_roll/pitch/yaw`）と保持の目標（`whold_*`）も残す。

## シミュレーターのドリル

`arm_sim.py` は右手を外して、手首にドリルを付ける（重さはないので、重さは今までどおり `--payload-kg`）。IK の Redis `drill_cmd` が ON の間（追従中に右トリガー）、先が毎秒3回転で回り、モーターの2本の輪が緑になる。実際の回転数ではなく、映像で回っているのが分かる速さにしている（`--drill-rps`）。`--no-drill` で外せる。

形は仮のもの（アダプターが未完成のため）。実機と同じく右手は外し、手首の取り付け面（手が付いていた所）にアダプター、モーター、チャック（黄色の線）、ビット（平たい刃）が、前腕の向き（`right_wrist_yaw_link` の x）に並ぶ。取り付け面から先端まで約24cm。手のメッシュには重さがないので、外しても物理は変わらない。IK が動かす点は今までどおり `right_rubber_hand`（取り付け面の位置）。

状態は `sim_qpos` の `"drill": {"on": 0/1, "angle": rad, "rps": 回転/秒}` に入る。`sim_qpos` から絵を描くビューアーは、次の3行で同じドリルを出せる。

```python
import sim_drill
sim_drill.add_drill(spec)            # MjSpec.from_file(...) のあと、compile() の前
view = sim_drill.DrillView(m)        # compile したモデル
view.apply(m, msg.get("drill"))      # 毎フレーム、mj_kinematics / mj_forward の前
```

## ドリルと手の当たり判定

ドリルの当たり判定は仮の形（`sim_drill.COLL_CAPSULES`：取り付け面から、モーター・チャック・ビットを覆うカプセル3つ、約24.5cm）。G1 のモデルの手には当たり判定がないので、手には箱を足す（`add_hand_collision`）。

- IK（`--tool drill`、既定）：右腕＋ドリル、左腕＋左手の箱を、体（骨盤・胴・股関節・膝）から離し、左右の前腕どうしも離す（`--collision-margin`、既定4cm）。`--tool hand` はドリルの代わりに両手の箱で判定する（ドリルを付けていない実機用）
- 握っていない側の腕は、IK の計算の中でも止めておく。止めた腕を計算のあとで戻すと、反対の腕から離れる動きが消えてしまうため
- `arm_sim.py`：同じカプセルと左手の箱で、体や反対の腕との接触を数える（立ち姿勢では接触なし）
- 確認：自動テスト `--scenario drill_cross` で、右手を左の前腕の方へ持っていき、ドリルを向ける。`check_tool_gap.py` で、ドリルと左腕の距離が3.7cm、体とが4.0cm で止まることを確認した（クラウド）
